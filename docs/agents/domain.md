# Domain docs

This repo uses one domain context.

Before codebase exploration, read the root GLOSSARY.md and relevant
decisions in docs/adr/.

If either is absent, proceed silently. Domain-modeling creates domain
documents when terms or decisions are resolved.

Use glossary terms in issues, designs, code, and tests. If a proposed
change conflicts with an ADR, identify the conflict explicitly.

Keep glossary entries about domain concepts. Record architecture
trade-offs in ADRs.
